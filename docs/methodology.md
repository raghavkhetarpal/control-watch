# Methodology

## Data Sourcing
Data is sourced exclusively from the public SEC DERA (Division of Economic and Risk Analysis) Form N-PORT datasets. These datasets provide structured TSV files containing mutual fund portfolio holdings.

## Ingestion Methodology
1. **Download**: ZIP archives are fetched from SEC DERA.
2. **Verify**: File integrity and expected TSV structures are checked.
3. **Parse**: Python/Pandas is used to read TSV files, handling missing values and data type conversions.
4. **Normalize**: Flat files are transformed into a 3rd Normal Form (3NF) relational schema (Funds, Holdings, Filings).
5. **Load**: Data is bulk-inserted into PostgreSQL using SQLAlchemy.

## Control Methodology
Controls operate as deterministic, rules-based SQL queries against the normalized dataset.
- Each control has a clear logic definition (e.g., `WHERE quantity < 0`).
- Controls execute sequentially or in parallel batches.
- Any record violating the logic generates a row in the `exceptions` table.

## Risk Scoring Methodology
Risk is scored using a transparent, standard formula:
- **Inherent Risk** = Impact (1-5) * Likelihood (1-5)
- **Control Effectiveness** = Assessed value (1-5)
- **Residual Risk Score** = Inherent Risk * (6 - Control Effectiveness)
*All scales and threshold bands are illustrative analytical thresholds.*

## KRI / KCI / KPI Methodology
Metrics are aggregated periodically (e.g., daily execution runs).
- **KRIs** aggregate exception volumes and values by risk category.
- **KCIs** aggregate telemetry from the control execution logs (success rates, error rates).
- **KPIs** track system performance (ingestion time, API latency).
Trends are calculated by taking `(Current_Value - Previous_Value) / Previous_Value`.

## Exception Management Methodology
Exceptions follow a predefined lifecycle workflow:
1. **Open**: Exception generated by Control Engine.
2. **Investigating**: Analyst claims the exception for review.
3. **Closed - Resolved**: Data was corrected or underlying issue fixed.
4. **Closed - False Positive**: Analytical rule flagged acceptable data; control logic may need tuning.

## AI Methodology
The AI Copilot uses Evidence-Grounded Analysis.
- It is provided only with structured summary data (JSON format of recent metrics/exceptions).
- It is instructed via System Prompt to never hallucinate data and to base all observations purely on the provided JSON payload.
- It provides qualitative summaries of quantitative trends.

## Threshold Setting
All numeric limits, tolerances, and RAG (Red/Amber/Green) statuses defined in this platform are **illustrative analytical thresholds** documented for educational demonstration. Rationale for these defaults is based on common generalized reporting patterns, not specific institutional policies.
